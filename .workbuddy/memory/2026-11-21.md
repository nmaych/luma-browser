## 关键结论（重要）

- Electron 45 的内核**没有** `chrome.userScripts`、`chrome.cookies`、`chrome.webNavigation`、
  `chrome.contextMenus`、`chrome.downloads`、`chrome.tabs.create`。`ses.registerPreloadScript({type:'service-worker'})`
  在扩展 SW 里**不执行**（已验证）。
- 因此 Tampermonkey 这类扩展即使加载成功也拿不到 `chrome.userScripts`，脚本注入需用户在扩展设置里把
  「Content Script API」切到 Content Script（走它自己的注入路径）。这个默认值不能由浏览器代设，
  否则会影响其它扩展。不要在后续排查里再尝试注入 SW preload 或改 CSP 加 `unsafe-eval`（试过，无效）。

## 追加：下载项优先用文件自身的图标

- `electron/main/fileIcons.cjs`（新）：`fileIconFor(absPath)` 返回 `{ dataUrl, kind }`。
  图片（png/jpg/jpeg/webp/gif/bmp/avif/ico，≤24MB）走 `nativeImage.createFromPath` + 等比缩放到 96px
  → `kind:'thumbnail'`；其余走 `app.getFileIcon(path, {size:'large'})` → `kind:'shell'`，
  Windows 下即 exe 内嵌图标。缓存 key=规范化路径，值带 `size:mtime` 戳（LRU 256），
  失败结果也缓存避免每次进度 tick 重试；`forgetFileIcon` 在删除下载文件时调用。
- IPC 用 **下载 id** 而非路径（`downloads:icon`），避免渲染层读任意磁盘路径；`progressing` 状态直接返回
  null（半截文件不可描述）。
- 渲染层 `src/hooks/useFileIcon.ts`（新）：模块级 Map 缓存 + inflight 去重，`enabled` 为 false 时不发请求。
- `DownloadsPage.tsx` 抽出 `DownloadIcon` 组件（hook 不能在 map 里调用）：有真图标时 img 铺满、
  背景改中性色、**隐藏扩展名角标**（真图标已表达类型）；读不到才回落到 lucide 图标 + 角标。
- 实测（Electron 内跑探针）：png → thumbnail 6010B/12ms，electron.exe → shell 3626B/108ms，
  package.json → shell；命中缓存 0ms。截图确认 exe 行显示 Electron 原子图标、图片行显示缩略图、
  缺失文件的 pdf 行仍是类型图标。测试：`tests/fileIcons.test.ts`、`tests/fileIconHook.test.tsx`。

## 更正与最终结果：1.20.0 已发布到 GitHub

前面对网络的判断只对了一半，实测后更正（以后再遇到同类问题先按这几条排查）：

- 沙箱设了 `HTTP(S)_PROXY=http://127.0.0.1:55865`，**git/curl 会走它**，它对 github.com 的 CONNECT 返 502，
  这也解释了 curl 的 0x80092012（代理的中间人证书 + 调不到吊销列表）。
- **Node 的 fetch（undici）不读 env 代理**，直连可达：`api.github.com` 200、`uploads.github.com` 200、
  `objects.githubusercontent.com` 404、`github.com` HTML 200；只有 git smart-HTTP 那条约 10s 超时/重置。
- 所以结论是：**没有 gh 也能发布，用 REST API；git push 不可用**。

落地物：`scripts/publish-release.mjs`（`npm run publish:release`），只用 Node，无依赖：

1. 本地 HEAD 不在远端时，用 git objects API 逐 blob 重建（校验返回 SHA == 本地 blob）、建 tree
   （校验 == 本地 root tree）、建 commit（校验 SHA == 本地 commit），最后快进 ref —— 源码与包严格同源；
2. release 正文从 CHANGELOG 对应版本段提取；已存在则 PATCH 正文；
3. 逐个上传 4 个产物，**回读下载算 SHA256 比对**，不一致删掉重传最多 3 次；
4. 校验 `releases/latest`、`latest.yml` 的 version、安装包 Range 返 206。
   另有 `--dry-run`（只读计划）与 `--commit-only`（只同步代码不动 release）。

踩到的两个坑：
- **commit SHA 重建不一致**：日期转换把 UTC 时间直接拼 `+08:00`，等于偏移 8 小时。要先加时区偏移再格式化
  成"该时区的墙钟时间"（`new Date((seconds + offset)*1000).toISOString()` + 后缀偏移）。
- GitHub 对未知 commit 返回 **422 "No commit found"**，不是 404，判断"提交是否在远端"两个状态都要接。
- 上传/回读要单独放大超时（15 分钟），默认 120s 会掐断 119MB 的传。

结果（已独立复核）：远端 `main = 07f87b1`（与本地一致）、tag `v1.20.0 -> bb31a63`、
release 非 draft，4 个附件尺寸与本地一致、公开下载地址 Range 返 206 且前 2 字节是 `MZ`。
凭据：用户从旧机拷来 `D:\downloads\gh-hosts.yml`（gh 的 hosts.yml 是**明文** oauth_token，可跨机拷贝；
凭据管理器里的 DPAPI 条目则拷不过来）。token 为 `nmaych`，scopes `gist, repo, workflow`。


## 1.20.1：图标 / 地址栏 / 扩展开页 / 登录态

- **下载图标真凶**：Windows 的 `app.getFileIcon` 对**所有** exe 返回同一个通用「应用程序」图标
  （实测 Git / FlClash / Qoder 完全一样），`nativeImage.createThumbnailFromPath` 在本机直接
  `Failed to get thumbnail`（IShellItemImageFactory 不可用）。结论：exe 只能自己解析 PE 资源。
  新增 `electron/main/peIcon.cjs`：走 DOS→PE→可选头→数据目录[2]→节表映射 RVA，再遍历
  资源树 type(14)/name/语言 → `IMAGE_RESOURCE_DATA_ENTRY`，取 GRPICONDIR 里最大的那张，
  PNG 直接 `createFromBuffer`，DIB 自己解成预乘 BGRA 交 `createFromBitmap`。只读偏移，不整文件读入。
  踩到两个坑：① 资源树里**每个 offset 都相对资源节起点**（不是相对当前目录）；
  ② 组的名字可能是字符串（高位置 1，如 Git 安装包），但 RT_ICON 仍按数字 id 对应；语言目录必须先下钻。
- **扩展开新页**：Electron 的 `chrome.tabs` 有 query/get/update/reload/sendMessage，**没有 create**，
  也没有 `chrome.windows`。做法：扩展窗口（dashboard + 弹窗）用 `contextIsolation:false` + 专用
  preload `electron/extension-preload.cjs` 在页面主世界补上两个方法，IPC 转主进程，主进程只放行
  http(s) 与自己的 `chrome-extension://`，并校验来源 frame 是扩展页。
- **登录态丢失**：cookie 只在网络服务正常关闭时落盘，更新是安装器从外部杀进程。退出前 `flushStore()`
  （1.5s 超时）；`configureUserData` 额外 `appendSwitch('user-data-dir', …)`，让 os_crypt 密钥与 cookie 库
  永远同一个目录。另发现 `%APPDATA%\Luma Browser` 有一份空的第二配置（不含 Partitions/Cookies），
  说明有启动走过默认路径 —— 这类分裂也会表现为"全部网站掉登录"。
- 验证：93 tests / 17 files（新增 `tests/peIcon.test.ts` 7 条，含自造 PE 二进制的合成测试）；
  运行态截图确认 Git/FlClash/ZIP/PDF 四个图标各不相同、地址栏 favicon+锁角标、首行"搜索xxx / 使用 百度"、
  Alt+Enter 标签数 2→3；关窗后进程正常退出（before-quit 未卡死）。
