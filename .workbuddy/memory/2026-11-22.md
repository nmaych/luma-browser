## 1.21.0：密码/画中画/用户脚本/翻译（提交 `c1ea8e4`）

- **密码存不下（全站）根因**：页面 preload 用 `ipcRenderer.sendToHost`，它只对 `<webview>` 宿主
  有效；Luma 页面是原生 `WebContentsView`，没有 host，消息被丢弃，所以任何网站都不会弹保存提示。
  改用 `ipcRenderer.send`（主进程 `wc.on('ipc-message')` 本来就在等这个通道）。B 站这类 XHR 登录
  不提交表单：补「密码框停止输入 1.2s」+ `pagehide` 捕获，`lastReport` 去重，避免一次登录弹两次。
  实测：本地表单提交 → 弹窗 → 保存 → `passwords.json` 有 1 条。
- **视频小窗失效**：1.19.0 就有菜单项，但只在顶层文档找 `<video>`。改为逐帧（`mainFrame.framesInSubtree`）
  探测，跳过 `disablePictureInPicture`，最多试 6 个视频并回报真实错误。实测 canvas+MediaRecorder
  造的本地视频，菜单点击后 `document.pictureInPictureElement` 为真。
- **篡改猴为何必然不行**（已实测确认）：Electron 45.2.3 的扩展页 `chrome.userScripts === false`、
  `chrome.tabs.create`/`chrome.windows`/`chrome.contextMenus` 都没有，只有 `chrome.scripting`。
  TM 5.4.1 是 MV3，全部注入走 userScripts → 装得上、打不开脚本。方案：内置用户脚本引擎
  `electron/main/userscripts.cjs`（解析 @match/@include/@exclude/@run-at，主世界执行，
  GM_setValue 等用站点 localStorage，GM_xmlhttpRequest 走 preload 的 postMessage 桥）。
  无痕窗口不注入。注意 match pattern **不含端口**，正则要给 host 补 `(?::\d+)?`。
- **翻译**：`edge.microsoft.com/translate/auth` 现在直接 404（换 UA/Origin 都一样），Google 在本机
  网络 `ERR_CONNECTION_TIMED_OUT`，LibreTranslate 公共实例全挂（502/403/域名不存在），只有 MyMemory
  可用。所以：去掉 Microsoft，加 DeepL（用户 Key，`:fx` 走 free 域），auto 模式 Google 与 MyMemory
  **错峰竞速**（0.7s 后同时起步，先回先用），并记住上次成功的 provider。MyMemory 单次 500 **字节**
  上限 → 按 UTF-8 字节切片。实测首翻从 7.7s 降到 1.5s，1100 字符英文 3.8s 成功。
  另加动态补翻：翻译后每 3s 收集新文本节点（`TRANSLATION_COLLECT_SCRIPT` 返回 offset），最多 20 轮。
- **拖拽文本到标签栏**：Windows 把 `-webkit-app-region: drag` 当标题栏，HTML5 拖放事件根本不触发。
  把 `.browser-tabbar`/`.tab-list` 改成 no-drag（窗口拖动留给品牌区 + 拖拽手柄）。
- **地址栏首击全选**：`onMouseDown` 记标记，`onMouseUp` preventDefault 再 select()；只靠 onFocus 的
  select() 会被随后的 mouseup 覆盖。
- **右键全选选到地址栏**：`document.execCommand('selectAll')` 在焦点回到地址栏时会选中 URL；
  改成只处理右键命中的 field，否则选 `.web-content`。
- 其他：右键截图只留「截取选定区域」；选中文字可开新标签页（网址）或新标签页搜索；地址栏 10 个

  书签图标启动校验（缺失/无法解码/超过 7 天 → `refreshFavicon` 绕过缓存重取）；页面开

## B 站首页轮播空白（1.21.1）

- 现象：首页左侧轮播只剩灰底 + 圆点 + 箭头，标题和图片都没有。
- 排查关键结论：与本项目的广告拦截**无关**（用户的 `userData` 下根本没有 `adblock/` 缓存，
  规则引擎从未加载成功，`cosmetics()` 返回 null，被拦请求 0 条）。也非 UA / 宽度 / 缩放问题。
- 真因（站点自身缺陷）：`.vui_carousel` 有 11 个 `.vui_carousel__slide`，其中两个广告占位是
  0 宽度节点，分页圆点只有 9 个。站点索引会走到 `--translate-x-slides: -900%/-1000%`，
  超过 `-(dots-1)*100%`，视口停在轨道之外的空白处，持续数秒；点任意圆点即可恢复。
- 复现手段：`electron . <url> --user-data-dir=<profile 副本> --remote-debugging-port=9333`，
  再用 Node 全局 `WebSocket` 走 CDP 采样 `document.elementFromPoint` / 幻灯片 `getBoundingClientRect`。
  **隐藏的 BrowserWindow 抓不到**（`probe-control` 150 秒 0 次），必须跑真实应用实例。
- 修复：新增 `electron/main/site-fixes.cjs`（按 host 分发的站点补丁），`dom-ready` 时注入。
  bilibili 补丁只在「没有任何可用幻灯片与可见区重叠」连续 2 拍（400ms/拍）时点下一个圆点，
  站点自己显示「内容被插件屏蔽」提示时不介入，修复后 1.5 秒冷却。
  实测 150 秒内 4 次 `-900%` 越界，全部在 1 秒内被修好，无误报点击。
- 质量门：`tsc -b` 干净，`vitest` 104 passed（新增 site-fixes 4 条），`vite build` 通过。
  版本升到 1.21.1（`package.json` + 设置页两处兜底值），提交 `726b067`（未推送、未打包）。

### 更正：真因是「广告拦截把空广告位那一张隐藏了」

- 上一段写「与广告拦截无关」是错的：那时用的探测实例还没下载完规则（`engine=builtin`、
  `cosmetics()` 返回 null），所以看不到。规则引擎加载后现象立刻出现。
- 实测链路：EasyList 的 `.vui_carousel__slide:has(img[src$="/eva.png"])` 把 B 站「空广告位」
  那张（`eva.png` 是 689 字节占位图）隐藏 → 该 slide 宽度变 0 → 可用 9 张、圆点 9 个，
  但站点索引仍走 11 步 → `-900%/-1000%` 越界 → 灰块。
- 对照实验（Edge 真窗口 + CDP，`--remote-debugging-port=9444`）：Edge 3 分钟内同样出现 4 次
  索引越界，最长 5.3 秒，但 11 张幻灯片都是全宽，越界时仍有内容 → 从不空白。
  所以「其他浏览器不会」= 它们没隐藏那一张，不是 Luma 特有缺陷。
- 曾在 `adblock.cjs` 加过「对 bilibili 过滤掉 `.vui_carousel__slide` 选择器」的例外，实测
  幻灯片变回全宽但会看到站点自己的灰色占位页 5 秒，比原来更难看 → 已回退。
- 最终：保留拦截，把补丁提速到 200ms 轮询 + 越界立刻点圆点（不再等 2 拍）。
  实测 150s / 1202 次采样（125ms 一次）**0 次可见空白**，4 次越界全部即时纠正。
- 提交：`726b067`（初版）、`694adb2`（提速 + CHANGELOG 更正）。

## 1.21.3：灰白轮播的真因是站点自己的提示板（17:35–18:05）

- 用户装上 1.21.2 后仍报「还是不行」，指向 `D:/LumaBrowser/Luma Browser\LumaBrowser.exe`
  （核对 asar：确实是 1.21.2）。
- 复现前提：**必须用装好的 exe + 真实 profile 的副本**（robocopy 排除各种 Cache，
  36MB；`MSYS_NO_PATHCONV=1` 才能让 Git Bash 正确传参给 robocopy）。
  另外探测进程会被后台节流到 1Hz，要加 `--disable-background-timer-throttling`
  `--disable-renderer-backgrounding` 才能抓到短促异常。
- 真因 1（灰白轮播）：每张幻灯片里都有 `.extension-tips-v2`——站点自己的
  「该内容被 AdGuard/AdBlock 类插件屏蔽」提示板，`rgb(241,242,243)`、与幻灯片同尺寸。
  规则表只隐藏里面的 `.tips1`/`.tips2`，**底板留在原处盖住海报** → 看上去就是白到灰渐变。
  隐藏整块底板后轮播立刻正常（截图对比确认）。
- 真因 2（右下角错位）：A/B（`setAdblockSite('www.bilibili.com', true)`）证明
  `hidden` 从 4 → 0、网格从 6 个空格 → 完整。规则表的
  `##.container > div.feed-card:empty` 会把广告位卡片整张删掉，站点不回收格子，
  整行左移/错位（这就是之前量到的「封面比同行低 37px」的真正来源）。
- 修法：新增 `siteStylesFor(url)`（`electron/main/site-fixes.cjs`），
  `applyCosmeticFilters` 把它拼在规则表 CSS 之后插入；用 `:not(#luma-grid-keep)`
  提高优先级压过规则表的 `!important`，不动规则表本身。
- 判据教训：DOM 里有图 ≠ 画出来了。**用 `document.elementFromPoint(中心点)`** 判轮播是否
  真有内容，否则「有图但被底板盖住」会被误判成正常（1.21.2 的检测就是这样被骗过的）。
- 验证（打包版 1.21.3 + 真实引擎 + profile 副本）：网格 27 项 `hidden=0`、每行
  `[4,3,5,5,5,5]`；11 块提示板 `platesVisible=0`；轮播 604 次采样空白 0、被底板覆盖 0。

  `default_app.asar` 被系统锁住（safe-delete 也失败），改到 `release/1.21.3b` 打包再把
  产物拷回 `release/1.21.3`。

## 1.21.4：空壳卡片的真因是「掏空」而不是「删除」（18:15–18:50）

- 1.21.3 装好后用户报：图片回来了但下方文字没有、轮播下方和右方的视频没了。
- 用户窗口尺寸记录在 `User Data/window-state.json`：`1440x900 maximized` —— **复现必须用
  1440 宽**（网格 5 列 × 245px，轮播占 2×2 格）。
- 决定性方法：不只看 DOM 有没有图，要判断**封面/标题的 rect 是否真的落在卡片盒子内**
  （`r.left >= box.left - 6 && r.left < box.right` 且尺寸 > 30×10）。空壳卡片在 DOM 里
  有 `img.naturalWidth=672`、有标题文本，但两者 rect 都是 0 或跑出盒子。
- 真因（逐层回溯算出来的）：规则表
  `.bili-video-card.is-rcmd:has(> .bili-video-card__wrap .bili-video-card__stats--icon > path[d*="M16.9122…"])`
  把**内层** `.bili-video-card` 设成 `display:none`，`-3000px` 那组又把封面链接
  （`.bili-video-card__wrap > a[href^="http"]:not([href*=".bilibili.com/"])`）和
  `.bili-video-card__info` 挪出屏幕。外层 `.feed-card` 格子尺寸不变 → 一个 245×213 的空盒。
- **关键教训：这个网格的 `grid-template-rows` 是站点写死的固定值，删卡片不会重排。**
  试过 `display:none` 折叠空卡 → 行内卡片上下错开约 40px，且 `align-self:start`、
  `grid-auto-flow:dense`、`grid-template-rows:none !important`、手动触发 resize 都救不回来。
  「删卡保排」是死路，只能把卡片放回格子里。
- 修法：站点样式加
  `body .container .bili-video-card.is-rcmd` / `.bili-video-card__info` /
  `.bili-video-card__wrap > a` → `display:block; visibility:visible; position:relative; left:auto`
  （`:not(#luma-grid-keep)` 提权压过规则表的 `!important`）。
- 验证（安装版 1.21.4 + 真实 profile 副本 + 1440 宽）：修复前每次加载稳定 **2 个空壳格**
  （590,498 与 325,771），修复后 **0 个**，网格几何完全不变（无位移/无重排）。110 测试通过。
- **代价（要向用户说明）**：空壳格就是 B 站原生推广卡片，放回去等于首页每屏有 1–2 张带
  「广告」角标的卡片。想完全不看广告就只能接受空洞或错位（站点不重排）。
- 安装方式改进：NSIS 的 `/D=` 在 Git Bash / PowerShell 里都会被空格吞掉（上次装到
  `D:\LumaBrowserLuma Browser`）。现在改为把 `release/<ver>/win-unpacked` 用 robocopy
  覆盖进 `D:\LumaBrowser\Luma Browser`（先备份 `resources/app.asar.bak-1213`），
  再用 asar 里的 `package.json` version 验证，等价于原地更新且不碰注册表。

## 1.21.6：站点开关不生效的真因是「设置从来没写盘」（19:20–20:05）

- 用户报「关闭对此网站的广告拦截，还是在拦截」。实测（安装版 + 临时 profile 副本 + CDP）：
  启用时 226 个请求里 73 个被拦；`setAdblockSite(host,true)` 后重载 0 个被拦 → **当次会话是生效的**。
- 真因在 `createSettingsWriter(appSettingsPath, ...)`：传进去的是**函数**（为了延迟解析
  profile 目录），`fs.writeFileSync(函数, …)` 每次抛 TypeError 被 `catch` 静默吞掉，
  于是 `disabledSites`、老板键、快捷键、`blockedTotal` 从来没落盘，重开就回到默认。
  修法：`resolvePath = typeof filePath === 'function' ? filePath : () => filePath`，并补了两条测试。
- UI 也在骗人：菜单那行永远写「对此网站启用拦截」，暂停后徽标还挂着上一页的计数 →
  现在按状态显示「暂停/启用」，暂停时清计数、不显示徽标，`adblock:set-site` 立刻对已开页面
  移除/重加样式（不用等重载）。
- 画中画：新增 `electron/main/pip-button.cjs`，`dom-ready` 注入到所有 http(s) 页面；
  `mousemove` 命中 `<video>` 就在其右上角画一个 30px 圆角按钮（`position:fixed`，
  点击是真实用户手势，直接 `requestPictureInPicture()`，不走 IPC）。菜单里的「视频小窗」已移除。
- 小窗标题：先写 Media Session `MediaMetadata`，再把 `document.title` 换成视频标题
  （`og:title` → 标题节点 → h1 → 页面标题），退出小窗/失败时还原 —— 这样浮动窗口不会顶着网址。
- B 站提示板重新出现的原因（第二个坑）：站内自己的
  `.carousel .carousel-container .vui_carousel__slides .vui_carousel__slide .carousel-area
   .extension-tips-v2[data-v-…] { display:block !important }`（7 类 + 属性）压过了原来的两条类选择器。
  改成 `body .vui_carousel .carousel-area .extension-tips-v2:not(#luma-plate-keep)` 才赢。
  **注意元素层级是 `.extension-tips-v2 > .carousel-area-img`，不是 `.carousel-area` 的直接子元素。**
- 排查技巧：`insertCSS` 注入的样式**不会出现在 `document.styleSheets`** 里（扫描 cssRules
  永远是 0 条），要看是否命中必须用 CDP `CSS.getMatchedStylesForNode`（`origin: injected`）。
- 验证（1.21.6e 打包版 + 真实 profile 副本 + 1440 宽）：提示板可见 0、网格 27 项、轮播命中 IMG；
  `PERSISTED=true`、停用后 `blocked=0`、小窗按钮 `display:flex` 且落在视频右上角内。
